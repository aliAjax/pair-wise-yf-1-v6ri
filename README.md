# 冷链转运站 · 交接台

断网期间司机在车上逐箱登记箱号、封签号、版本和温度读数，回站后多个车次同时提交。
本交接台保证：旧温度和箱位不会被并发提交悄悄覆盖；重试不重复入库；箱子记录一变，
先前的有效交接立即作废并重算剩余箱位。

## 启动

```bash
npm start                 # 默认 http://localhost:3000
PORT=3210 npm start       # 换端口
SLOT_CAPACITY=30 npm start  # 初始总箱位（默认 24，页面上调度员也可改）
```

无第三方依赖，Node 18+ 即可。

演示账号（密码均为 `123456`）：

| 账号 | 角色 | 权限 |
| --- | --- | --- |
| `driver1` / `driver2` | 司机 | 只能提交本车次（TRIP-01 / TRIP-02）的批次 |
| `dispatcher` | 调度员 | 处理冲突、调整箱位、兜底采信失败行 |

## 页面用法

- **司机**：在“登记交接批次”里填车上生成的批次号（断网离线生成，重试用同一个号），
  每行一箱：`箱号,封签号,版本,读数`，例如 `A001,SL-8801,0,4.2`。
- 首页按要求列出：**待处理交接（冲突队列）**、**箱位余量**、**失败行与原因**，
  另附全部批次、已作废交接、箱子当前记录和调度审计。
- **调度员**对冲突二选一：`采信车上`（覆盖当前记录，旧交接自动作废、箱位重算）
  或 `维持在站`（冲突行转为失败，不动在站数据）。

## 判定规则（src/judge.js）

| 情形 | 结果 |
| --- | --- |
| 站内无该箱 | 正常入库，建立当前记录并占一个箱位 |
| 封签号与读数都与在站一致（干净箱） | 正常返回，但**不重复占位** |
| 封签号或温度任一不同 | **冲突**，进入待处理队列，绝不覆盖在站记录 |
| 提交版本低于在站版本 | 失败（旧底单），给出版本原因 |
| 缺箱号/封签、版本或读数非法、同批箱号重复 | 失败并标注行原因 |
| 新箱但箱位已满 | 失败；已在站的干净箱重复交接不受影响 |

## 存储与并发语义（src/store.js）

- 批次号是幂等键：**同批重复提交（含失败后的重试）原样取回首次结果**，批次先落账再判行，
  因此失败重试也不会重复入库。
- 箱子的当前记录一旦因“正常新交接”或“调度员采信冲突”而变化，
  该箱其它批次里此前 `accepted` 的交接行立即置为 `voided` 并记录作废原因；
  箱位余量按“当前仍有效交接的去重箱号”实时重算。
- 所有写入原子落盘到 `data/handover.json`（临时文件 + rename），
  **服务重启后批次、冲突、余量、失败原因、作废留痕都还在**；登录会话会重置。
