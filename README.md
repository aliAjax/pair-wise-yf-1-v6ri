# 冷链转运站 · 交接台

断网补录场景下的交接台：司机在车上登记箱内温度与封签，回站后多车次同时提交。
同批重复提交取回首次结果；换封签/读数返回冲突；箱子当前记录一变，先前交接立即作废并重算箱位。

## 启动

```bash
npm install
npm start
# 打开 http://localhost:3000
```

数据落本地 SQLite（`data/transfer.db`），服务重启后仍可查询。

## 三个业务文件

| 文件 | 职责 |
|------|------|
| `lib/store.js` | **批次存储**：批次、箱子当前记录、箱位容量的本地 SQLite 持久化 |
| `lib/adjudicate.js` | **交接判定**：幂等、冲突、先前交接作废、箱位余量重算（纯逻辑） |
| `lib/page.js` | **页面操作**：页面数据汇总、提交/驳回操作、整页 HTML 渲染 |

`server.js` 是入口（Express 路由 + 身份切换），`public/` 是前端样式与脚本。

## 业务规则

- **批次**：每个交接批次带 `批次号 batchId`（幂等键）、`车次 tripId`、`箱号 boxNo`、`封签号 sealNo`、`版本 version`、`读数 readings`（时间+温度）。
- **同批幂等**：同一 `batchId` 重复提交，内容一致 → 取回首次结果，不重复入库；内容被改（封签/读数/版本）→ 返回冲突，首次结果不被覆盖。
- **数据过期**：新批次的封签/读数与箱子当前记录不一致 → 冲突（`箱内记录已变更，本批次数据过期`）。
- **作废重算**：箱子当前记录一更新（新交接成立或调度员强制接受），该箱子先前交接立即作废，箱位余量逐位重算。
- **失败不重复**：冲突后重试同一批次，取回冲突结果，不新增记录。
- **角色权限**：司机只能提交本车次（车次以身份为准）；调度员可处理冲突（接受 / 驳回）。

## 页面

- **待处理交接**：未决与冲突批次，调度员可在此接受/驳回。
- **失败原因**：冲突、驳回、作废批次及原因。
- **箱位余量**：各箱位总容量 / 已用 / 余量。
- **箱子当前记录**：每个箱子的当前封签、版本、读数、箱位、当前批次、记录版本。

## 接口

- `POST /api/batches` — 司机提交交接批次
- `POST /api/batches/:batchId/resolve` — 调度员处理冲突（`action=accept|reject`）
- `GET /api/dashboard` — 页面数据
- `POST /api/identity` — 身份切换（driver/dispatcher）
